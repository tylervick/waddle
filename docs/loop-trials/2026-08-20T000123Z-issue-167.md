Issue #167: `DiagnosticsMetricSubscriber` implemented only the
`MXDiagnosticPayload` half of `MXMetricManagerSubscriber`. Both callbacks are
optional, so the missing one was silent — the app subscribed and dropped a
metric payload a day. Reproduced at HEAD by reading the class: one `didReceive`,
no `MXMetricPayload` overload, and `MXMetricManager.shared.add` wired up in
`WaddleApp.init`.

The issue's real content is the design hazard, not the callback. Metric payloads
arrive daily and diagnostics only on failure, so routing both into one store
with its cap of 10 evicts every crash report in about ten days. Chose separate
directories (`Diagnostics/Metrics/`) with a separate count (30): retention prunes
by enumerating one directory, so the guarantee is structural rather than resting
on two filename prefixes staying disjoint. The distinct `mxmetric-` prefix is
only for legibility in the flattened export zip.

The issue demanded the eviction test be proved discriminating rather than
assumed so, and that was worth doing: with the subscriber temporarily wired to
one shared store, `testMetricPayloadsNeverEvictADiagnosticPayload` failed with
the diagnostics directory holding 10 files, all metrics — the surviving payload
was `{"metric":51}` where the crash report should have been. Restoring the split
turned it green.

Two things cost time and neither was the work. First, `mise run bootstrap`
failed outright in this fresh Orca worktree: the copied, gitignored
`Vendor/build` carries CMakeCache files naming the owner's primary checkout.
That is trap 2 in `docs/learnings/worktree-setup-traps.md`, already documented —
`rm -rf Vendor/build` and rebuild, about eight minutes. Worth knowing that every
per-run worktree will hit it, and that it surfaces in `build-deps`, not
`build-engine` as the learning's wording suggests.

Second, the issue's verification command cannot run as written: it names
`App/WADdle.xcodeproj -scheme WADdle -only-testing:WADdleTests`. The project path
resolves on a case-insensitive filesystem, but scheme names are matched exactly,
so it fails with `does not contain a scheme named "WADdle"` before testing
anything. The retired stylized spelling is the subject of
`docs/learnings/the-name-is-waddle.md`; `Scripts/check-name-consistency.sh` sweeps
the repo but nothing sweeps issue bodies. Ran the same command with the real
names (`Waddle`/`WaddleTests`) — `** TEST SUCCEEDED **`, zero failures across the
target — and flagged the wording in the pull request so the issue text can be
corrected.

Also of note: the 1Password SSH agent was locked by the time section 4.2 pushed

(`agent refused operation`, then `The agent has no identities`). The documented

had both succeeded earlier in the same run, so the agent locked mid-run rather
than being unavailable from the start — a run that only ever pushes late would
read this as a total failure.
