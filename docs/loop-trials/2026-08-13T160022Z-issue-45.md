`OverlayButton` draws a circle (`layer.cornerRadius = size / 2`) on a square
`UIView` and never overrode hit-testing, so all four frame corners fired the
button. Reproduced at HEAD exactly as the issue described, fixed with a
`point(inside:with:)` override that accepts only the drawn circle. PR #105,
CI green, CodeRabbit approved with zero findings and an empty review body.

Two things a reader in six weeks might want.

**The interesting design question was what the test could observe.** The
issue's verification command names the UITest suite, and "the button's action
never fired" has no existing observable: the overlay is torn down the instant
the session ends, so nothing can be read off it live, and a corner tap that
correctly falls through to `TouchOverlayView` produces no SDL event in the
default classic scheme either — so the existing `touchEventCountLabel` cannot
tell "missed the button" from "hit it". I added
`OverlayButton.debugPressCount`, cached across the session and surfaced by
`ContentView` under `WADDLE_DEBUG_INPUT_COUNTS`, which is exactly the shape
`TouchGamepad.lastFireReleaseTriggerResidue` already uses next to it and for
the same reason. The UITest then taps FIRE twice — once at normalized
(0.08, 0.08), ~6.7pt inside the square frame and ~50pt from centre against a
42pt radius, and once dead centre — and asserts the count is 1. Worth noting
that this coordinate is only addressable *because* the fix deliberately does
not touch the accessibility frame: XCUITest computes the corner from the
still-square element frame, and shrinking that would have made the test
impossible to write.

I also added `App/Tests/OverlayButtonHitAreaTests.swift`, which pins the same
geometry directly. That is not redundancy for its own sake: CI runs
`-only-testing:WADdleTests` and the UITests belong to a separate manually
dispatched workflow, so without the unit suite this change would have shipped
with no CI coverage at all and the red-green proof would have had nothing to
measure. It read `proved` / `swift`. I also checked red-green by hand before
committing, by neutering the circular test and running the UITest alone: it
failed with `("2") is not equal to ("1")`.
