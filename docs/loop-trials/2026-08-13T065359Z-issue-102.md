The work: `changelog()` no longer lets an empty merge-commit body degrade
a bullet to git's `Merge pull request #N from branch` subject. Recovery
order: the PR's title (the fetch is now split into pr_fetch + pr_title /
pr_summary so title recovery and prose decoration share one GET), then
the merged branch's tip commit subject when the API is unreachable —
local, free, the PR title in practice for single-commit branches, and
conventional-commit-prefixed so grouping still reads a real signal
offline. Grouping always runs on the recovered title. Case 9, which had
pinned the degraded subject as intended, was rewritten per the issue;
cases 31–33 pin the recovered-title flow, the offline fallback, and the
docs-misgrouping the issue measured.

Worth knowing in six weeks: the issue's required break/restore proof
caught a real test-design miss. Case 31 as first written (feat(library)
title + usable body) passed against the BROKEN script, because the old
code already decorated reachable PRs with the body sentence and the
recovered title's group coincided with the unparseable-subject default.
The fix was to make grouping the discriminator: a tooling-scoped
recovered title (feat(loop) → behind the scenes) against an unparseable
tip subject, so the case fails both if recovery never runs and if it
skips the API for the tip subject. Two breaks were proven: recovery
disabled entirely fails cases 9/31/32/33; API-skipping recovery fails
exactly 31/33. "A case that passes against today's behaviour is not
covering this" earned its place in the issue template.
