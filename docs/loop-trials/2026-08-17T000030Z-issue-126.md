Issue #126: spec §4's first-launch welcome card. In factory state the hero zone
now shows app name, one line, and a primary **Add Your Games** button; the
Freedoom tiles stay on the shelf below it, so the app is still playable in one
tap with zero setup. PR #177, CI green, CodeRabbit approved with no actionable
comments.

**Reproduced before fixing**, trivially and conclusively: `grep -rn
"welcome\|Add Your Games"` over `App/` returned exactly one hit, in a bundled
GPL licence text. There was no card, and `ShelfView`'s hero zone was
`if let heroItem` and nothing else — on a factory-state library the zone was
simply empty. The condition the issue describes was real at HEAD.

**The two judgment calls, both of which a reader should check first.**

1. *The dismissal rule asks the whole library, not `shelfItems()`.* A mod
   imported from the share sheet is never a shelf item (`shelfItems()` is IWADs
   plus presets), and neither is a hidden row. Both nevertheless mean the
   player's own files are in here, and greeting them as a new arrival
   afterwards would be wrong. The test named
   `testAnImportedModEndsFactoryStateThoughItNeverReachesTheShelf` pins that
   reading, and it is the test that would fail first
   if someone later rewrote the rule over the shelf's own list — which is the
   obvious-looking way to write it.
2. *"Any save" means any save file, not a resumable one.* The Continue hero is
   deliberately strict about that distinction because it offers to boot the
   save; this rule only asks whether the player has got as far as playing at
   all, and a save the engine cannot resume still answers yes. So the two
   predicates on this screen are intentionally different, which reads like an
   inconsistency until you know why.

**The zone is one value, not two questions.** `Shelf.heroZone` returns
`welcome` / `resume(item)` / `empty`, so the card and the Continue hero cannot
both occupy the zone and cannot both be missing when one is owed. They are
mutually exclusive by construction anyway — a resumable save is a save, so a
library with a hero is not a factory-state one — but the hero is checked first
on purpose: if the two ever did disagree, a returning player should get their
game back rather than a greeting. `HeroZone`'s `Equatable` is hand-written
because `PlayableItem` wraps SwiftData models and has no synthesised one; it
compares `id`, which is what identifies an item everywhere else on the screen.

**Discrimination proved by hand, both dimensions, before pushing** — the issue
asked for the import probe; the save probe was cheap and worth having:

- Drop the non-bundled check from `isFactoryState()` →
  `testWelcomeCardIsGoneOnceANonBundledItemExists` and the mod case fail, and
  *nothing else does*. The factory and save cases stay green.
- Drop the saves check → `testWelcomeCardIsGoneOnceABundledGameHasASave` fails
  alone.

Restored, 314 unit tests pass (309 before, 5 added). Every new case seeds the
real bundled Freedoom rows via `seedBundledContentIfNeeded()` first, so
"factory state" is the state a genuine first launch is in rather than an empty
store, which no install is ever in.

**What is worth reading in six weeks: `test_proof_first: proved-by-compile`
again, and this time the mechanism is nailed down rather than guessed at.**
Run 42's record supposed it "presumably reflects the harness's own revert not
compiling rather than a weak test". Reading `Scripts/check-red-green.sh:339`
confirms exactly that: the harness reverts the *source* files only, keeps the
new tests, and runs `build-for-testing` — and any change that adds new API
alongside tests calling it cannot compile once that API is reverted away. Here
the tests call `service.isFactoryState()`, `Shelf.heroZone` and
`Shelf.HeroZone`, none of which exist at base. So `proved-by-compile` is
structural for this shape of Swift change, not a comment on test strength: the
hand probes above show these tests fail *selectively and on the right
dimension* when the logic is broken while the API stays. Recorded and not
acted on, per the protocol — the point of noting it is that a reader comparing
trials should not read `proved-by-compile` as a weaker trial than `proved`
when the change adds API, because in that shape `proved` may not be reachable
at all.
