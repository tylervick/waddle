Issue #118: recognized commercial IWADs should show their published game
titles instead of raw filenames. Reproduced immediately and unambiguously —
`LibraryService.registerImported` built `displayName` from
`(filename as NSString).deletingPathExtension` and nothing downstream ever
enriched it, so the Play tab showed whatever the file was called.

Shipped `IWADCatalog` (content SHA-1 → published title) and made
`registerImported` prefer it, falling back to the filename stem for everything
unrecognized. Import already computes that exact hash to dedupe on, so
recognition was nearly free; keying on content is what makes a renamed
doom2.wad still read "DOOM II: Hell on Earth".

**The interesting part was the data, not the code.** The mechanism is about
fifteen lines. Most of the run went into sourcing six published hashes and
corroborating each against two independent sources, because this table has a
failure mode nothing else in the app has: a wrong hash does not throw, does not
fail a test, and does not look wrong — it simply never matches, and `nil` is
the *designed* answer for every PWAD ever imported. A hash database whose URLs
*are* the SHA-1 turned out to be the useful verification trick: the fetch
succeeding is itself a check, and the MD5 on the returned page corroborates
independently. That trap is now
`docs/learnings/content-hash-tables-fail-silently.md`.

The same property dictated the test shape: the catalog tests spell hash
literals out instead of iterating `titlesBySHA1`, since a test built from the
table passes against an empty table. Verified by doing it — removing Plutonia's
row failed exactly `testResolvesThePublishedPlutoniaHash` and left the other
eight green. Reverting the `registerImported` change failed exactly the two
recognized-title import tests, with the rename case reporting
`["doom2", "renamed-by-the-user"]` — literally the parity defect the issue
describes. 241 tests pass, 13 new.

**Deliberately not covered:** SIGIL, which the issue names in its example list.
Its several versions and with/without-MP3 variants each hash differently and I
could not corroborate any of them to the two-source standard the other entries
met. Given the silent-failure property above, a guessed entry would be strictly
worse than no entry — it would sit in the table looking correct forever. Noted
in the pull request; adding it later is one line.

**Environment note, already-known trap:** `mise run bootstrap` failed on first
run because this worktree inherited `Vendor/build/` with CMakeCache files
hardcoding the primary checkout's path — exactly trap 2 in
`docs/learnings/worktree-setup-traps.md`. `rm -rf Vendor/build` fixed it and the
rebuild took only 92s, so the existing learning was accurate and sufficient; no
new file needed for it.
