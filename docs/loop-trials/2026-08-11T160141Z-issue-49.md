One thing already worth noting: the run could not use SSH for git at all. The
1Password SSH agent's socket exists but `ssh` gets `communication with agent
failed` from it, `ssh-add -l` reports no identities, and a retry did not
recover it — the agent is locked and an unattended run has no way to unlock it.
All network git in this trial therefore goes over HTTPS with `gh`'s token, via
per-command `-c credential.helper='!gh auth git-credential' -c
url."https://github.com/".insteadOf="git@github.com:"` flags, in the same
spelled-out-per-command style section 0 requires for the signing identity.
Commit signing itself is unaffected: `ssh-keygen` signs from the
`~/.ssh/waddle-agent-signing` file directly and never consults the agent.
