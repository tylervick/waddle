PR #161 for issue #94: the Read This! help screens killed the session when a
WAD lacked its help lump. Clean run — CI green, a real CodeRabbit review with
no actionable comments, no fix rounds needed.

**The issue named three draw paths and was right about two of them.**
`M_DrawReadThis1` and `M_DrawReadThisCommercial` both go through
`V_CachePatchName()`, whose miss routes into `W_GetNumForName()` and its hard
`I_Error("%.8s not found!")` at `w_wad.c:387` — exactly the string the
TestFlight reports carried. But `M_DrawReadThis2` was already calling
`W_CheckNumForName()`, which reads like it is guarded. It is not: it never
looks at the `-1` and hands it straight to `V_CachePatchNum()`, which
bounds-checks only the upper end (`lump >= numlumps`) before indexing
`lumpcache[-1]` — a heap array of exactly `numlumps` entries. So the third
path fails differently and worse than the two that motivated the issue: an
out-of-bounds read rather than a clean abort. Same guard fixes all three,
but a reader skimming for `W_GetNumForName` would have marked that one safe
and moved on.

**Reproduction was static, and I want to be honest about that.** The chain
from the menu entry to `I_Error` has no branch in it other than lump
presence, and `M_Init()` binds `ReadDef1.routine = M_DrawReadThisCommercial`
whenever `gamemode == commercial`, so a HELP-less commercial IWAD reaches it
straight from the main menu — which is the TNT.WAD case in the provenance. I
did not drive a simulator to the help screen; that needs an app build plus UI
navigation and did not fit the budget alongside a full engine rebuild. What I
did do is check the data instead of trusting it: parsed both bundled IWADs'
lump directories (`freedoom2.wad` has `HELP` and `CREDIT`, `freedoom1.wad`
has `HELP1`/`HELP2`/`CREDIT`, neither has a `W_HELP` widescreen variant — so
`W_CheckWidescreenPatch("HELP")` returns plain `"HELP"`, matching the
reported error), and rebuilt a `freedoom2.wad` copy with `HELP` dropped and
its directory/offsets fixed, then re-parsed it to confirm a well-formed 3609-
lump IWAD with no `HELP` and `CREDIT` intact. That last one is the exact
input the fix converts from a dead session into the credits screen, and it
also confirms the `CREDIT` fallback is not hypothetical. The end-to-end
behaviour still wants a human pass on a simulator; I said so on the PR.

**`test_proof_first: n/a` is not this change failing to prove anything.**
`Scripts/check-red-green.sh` scores two domains — `App/Sources` +
`App/Tests`, and `Scripts/*.sh` + `Scripts/test-*.sh`. A vendored-engine C
diff is in neither, so the script hits its empty-`domains` branch and prints
`n/a` / `domains: none`. Every engine-only trial will read this way until the
proof grows a C domain, and per the protocol I did not touch the change to
improve the measurement.
