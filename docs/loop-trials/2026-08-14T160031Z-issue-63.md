Issue #63 asked for a test that fails when `LibraryView.delete(_:)`'s
accumulation into `deleteBlocked` is reverted to a plain overwrite. The issue's
literal mutation (`deleteBlocked = names`) no longer type-checks — the code
moved on to a `BlockedFile` struct and a `blockedFiles` helper since the issue
was filed — so the equivalent shape was used:
`blockedFiles([], adding:for:)` instead of `blockedFiles(blocked, adding:for:)`,
which is the same defect (only the last blocked row survives a batch).

Reproduced first, as the protocol requires: with that mutation applied at HEAD,
**241 tests, 0 failures**. The gap was exactly as described.

The fix follows the reviewer's suggestion recorded in the issue's provenance:
`deleteBlocked` is `@State` and there is no view-testing harness, so the batch
loop was lifted out of the view into a static
`LibraryView.deleting(_:from:blocked:)` taking the WADs and the service.
`delete(_:)` now takes the whole batch, so `onDelete` maps offsets once rather
than looping. Behaviour is unchanged, including the seed from the current
`deleteBlocked` — that seed is deliberately kept and pinned by its own test, so
the only line left outside test reach is a one-line assignment.

Red-green, all three runs on iPhone 17 Pro with the issue's unmodified
`-only-testing:WADdleTests` command: 241/0 with the bug and no new tests →
244/0 on this branch → 244 tests with **2 failures** once the accumulation is
reverted again. The two that fail are `testDeletingABatchKeepsEveryBlockedRow`
and `testDeletingCarriesInAlreadyBlockedFiles`.

What surprised a reader might be `test_proof_first: proved-by-compile` rather
than `proved`. Recorded as measured and not acted on, per the protocol.

Two environment notes for whoever reads this in six weeks. First,
`mise run bootstrap` does not complete in a fresh Orca worktree: `build-deps`
dies because `Vendor/build`'s CMake caches carry the *primary* checkout's
absolute paths. That is trap 2 in `docs/learnings/worktree-setup-traps.md`,
already documented, so no new learning was added. The documented fix is
`rm -rf Vendor/build` and a full rebuild; that was skipped deliberately because
`Scripts/check-engine-fresh.sh` passes against the copied framework, so only
`fetch-freedoom` and `generate` were needed, plus staging `woof.pk3` from
`Vendor/build/woof-iphonesimulator/src/` exactly as `build-engine.sh:70` does.
Second, 1Password was locked for the whole run, so every fetch and push went
through the documented HTTPS-via-`gh` fallback; commit signing was unaffected
because the loop identity is a plain key file used with `ssh-keygen`.
