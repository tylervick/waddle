First run to actually work #13 — the earlier `2026-08-07-issue-13.md` is a
declared dry run whose `no-repro` is a harness placeholder, not a finding.

Reproduced at HEAD before changing anything: with `SDL_TAG` sed-bumped to
`release-3.2.16`, `Vendor/src/SDL` stayed on `release-3.4.12`. The fix makes
`fetch()` compare the requested tag against the checked-out commit and re-clone
on a mismatch. Verification ran unmodified and passed — `release-3.4.12`, bump,
`release-3.2.16`, both `build-deps.sh` runs exiting 0. PR #55.

Three things a human would want to know:

1. **The verification is far cheaper than it reads, but only on a warm tree.**
   It invokes `./Scripts/build-deps.sh` twice, which sounds like two full SDL +
   OpenAL builds for two platforms. In practice the whole run was ~90 seconds:
   the first invocation is a no-op reinstall, and the second rebuilds only SDL.
   A from-scratch build of both deps, both platforms, was ~110 seconds here.
   That is much faster than the engine build this repo's other work needs, so
   the 45-minute budget was never in danger — 10 minutes end to end.

2. **A fresh Orca worktree cannot run `build-deps.sh` at all until
   `Vendor/build` is cleared**, which cost the first attempt. Orca copies the
   gitignored `Vendor/` tree in from the owner's checkout, so every
   `CMakeCache.txt` carries `/Users/tyler/Documents/doom-ios-2026` hardcoded and
   cmake refuses immediately. This is already written down —
   `docs/learnings/worktree-setup-traps.md` trap 2 — so no new learning was
   added for it, but it is worth knowing that it lands on *any* build script in
   a loop worktree, not just `mise run build-engine` as that file frames it.
   Removing the four `SDL-*`/`openal-soft-*` build dirs was enough; the `woof-*`
   ones were left alone.

3. **Stale cmake caches across a version change turned out not to matter.** The
   worry was that `Vendor/build/SDL-iphoneos`, configured for 3.4.12, would
   choke when the source underneath became 3.2.16 — which would have forced the
   fix to invalidate build dirs too, well beyond the definition of done. It
   reconfigured and built cleanly, so that scope stayed out. Checked
   empirically rather than assumed; worth re-checking if a future pin crosses a
   larger version gap.

The new learning is about the test, not the fix: a hermetic test that builds a
git fixture inherits the owner's signing config, and `tag.gpgSign` announces
itself as `fatal: no tag message?` — an error that names neither signing nor
config. Same shape as this protocol's own section 0, one layer further in.

One thing left undone, deliberately: `.github/workflows/ci.yml` lists the helper
tests by name, so `Scripts/test-build-deps.sh` will not run in CI until a line
is added there. Workflows are off-limits to this loop, so the PR asks the owner
for that one line instead of taking it.

Protocol note: editing `Scripts/build-deps.sh` while a background copy of it was
running is a hazard worth avoiding — bash reads a script incrementally, so an
in-place edit can shift the bytes under the running parse. It happened here (a
comment-only rewording) and the run survived, but the verification was re-run
from a clean start rather than trusted, and the rule adopted afterward was to
finish edits before starting any run of the thing being edited.
