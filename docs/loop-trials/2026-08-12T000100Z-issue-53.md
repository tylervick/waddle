`EngineErrorAlert.hint(for:)` chose between its two wrong-IWAD hints with a
case-sensitive `message.contains("IWAD")`. Reproduced at HEAD before touching
anything: compiled the real source standalone (it only imports Foundation) and
fed it the same `D_AddFile` failure twice, differing only in filename case —
`/path/IWAD.wad` got "The base game file wasn't recognized", `/path/iwad.wad`
got the generic "needs a different base game". Same failure, different advice,
decided entirely by how the user capitalized their own file.

Fix is one line: `message.range(of: "IWAD", options: .caseInsensitive) != nil`.
Deliberately *not* `localizedCaseInsensitiveContains` — that is locale-tailored,
and in a Turkish locale the dotless-i mapping can make "IWAD" and "iwad" stop
matching, which is precisely the bug being fixed. The outer `wrongIWADMarkers`
array stays case-sensitive: those are literal engine-emitted symbols
(`W_GetNumForName`), not user-supplied text, and the issue scoped this to the
inner branch.

TDD held: the new test went red in the real harness first, failing only on the
casing divergence while the other 8 passed, then green after the fix.
