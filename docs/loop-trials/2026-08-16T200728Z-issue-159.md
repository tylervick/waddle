Issue #159: the Continue hero had no height cap, so on a landscape phone its
full-width 1.6:1 art (~504 pt) exceeded the whole viewport (~375 pt) and pushed
the grid — and the hero's own caption — below the fold. Fixed with a new pure
`ShelfHeroLayout`, the same shape as `TouchOverlayLayout`: viewport in, art
height out. PR #168, CI green.

**Reproduced before fixing**, though not the way the issue did it. The issue's
own evidence was a landscape screenshot capture; re-running that costs an engine
launch and a UI-test session, so the condition was confirmed at HEAD by reading
the code (`hero(for:)` constrains `maxWidth` and nothing else, so the art's
height is whatever 1.6:1 asks of full width) and computing the four device cases.
`Scripts/capture-screenshots.sh` independently corroborates it in a comment that
already names #159 as the reason its shelf shot shows the hero and nothing else.

**What surprised me, and is the thing worth reading in six weeks:** two
`WADdleUITests` failed in this run — `PlayTabTests/testBaseGameDetailControlsOverridePersists`
and `PresetEditTests/testEditFromDetailPageOpensEditor`, both "the detail sheet
never opens". The obvious inference after touching `ShelfView` is that the change
broke them. It did not: stashing the branch, regenerating the project and
re-running produced the identical two failures at HEAD. `ci.yml` runs
`-only-testing:WADdleTests` deliberately, so no pull request has ever run those
suites and they have been red without a red check anywhere. That is the learning
this trial added, because the trap is attribution — a future run that "fixes"
its own diff in response to them would be chasing a defect it did not cause.

**The one judgment call in the fix.** The issue's verification asks that
"iPad/portrait" not be shrunk. Portrait iPad is not (625 pt of art in a 1260 pt
viewport, 635 pt to spare). Landscape iPad *is* capped — 840 pt natural in a
916 pt viewport is the same defect in milder form, and the DoD's leading
sentence asks for room for the grid at every supported size. The cap there is
gentle (the hero keeps better than two thirds of the screen) and
`testLandscapePadIsCappedButStillDominant` pins that reading so it is visible
rather than smuggled in. If the owner disagrees, that test is the one line to
change.

`test_proof_first: proved-by-compile` — recorded, not acted on, per the
protocol. The new tests do discriminate, proved by hand before pushing: with the
cap replaced by `return natural`, 8 of the 12 `ShelfHeroLayoutTests` fail
(including the landscape-phone case), while `testPortraitPhoneIsUnchanged` and
`testPortraitPadIsUnchanged` stay green — they guard the opposite direction.
Restored, all 309 unit tests pass. `proved-by-compile` presumably reflects the
harness's own revert not compiling rather than a weak test, but that is CI's
verdict to explain, not this run's to improve.
