**What was built.** `Theme.tileAspectRatio` is 4:3; `PlayableTileView`'s title is
`lineLimit(1)`; the scrim's metrics moved into a new pure-geometry
`PlayableTileLayout` that the view draws from, with the top padding cut 28 → 16
so a one-line scrim is 48 pt, 37% of a 172 × 129 pt tile, under the 40% ceiling;
spec §5 records both owner decisions in its amendment style. 13 new tests in
`PlayableTileLayoutTests`, all passing. Both discrimination checks the issue
asked for behave exactly as specified: at `3.0 / 4.0` the height and scrim-share
cases fail, and restoring `.padding(.top, 28)` alone fails only the scrim-share
case.

**Why it is not green.** `ShelfHeroLayout.heroZoneBudget` computes the first tile
row's height as `gridColumnWidth(...) / Theme.tileAspectRatio`, so the tile's
shape is an input to the shelf's above-the-fold budget. Shorter tiles mean a
larger budget, which flips `testWelcomeCardDropsItsDescriptionOnTheCIPhone` from
false to true: on the CI phone at the pre-#205 200 pt floor the one-column tile
goes 493 pt → 277 pt tall, the hero zone goes 195 pt → 411 pt, and the welcome
card it asserts cannot fit now fits with 229 pt to spare. Final run: 384 tests,
1 failure, that one.

**It is caused by the constant and nothing else** — proved by toggling only
`Theme.tileAspectRatio` and rerunning: at 3:4 that test passes and the new tile
tests fail; at 4:3 the reverse. Its sibling
`testEverySupportedPhoneClearsTheFoldWithTheFullCard`, which uses the 150 pt
floor the product actually ships, passes either way — so the safety property is
strictly better after this change, not worse. A shorter first row leaves *more*
above the fold.

**What surprised me** is that the issue asserts the opposite: "`ShelfHeroLayoutTests`
covers the hero, which passes its own `ShelfHeroLayout.artHeight` and is
unaffected by `tileAspectRatio`." Half that file is the welcome card's budget,
which reads the constant through `heroZoneBudget`. The definition of done was
written on a false premise about the blast radius, which is what left no lawful
finish: there is no product change that keeps that assertion false except
reverting the aspect the owner decided on.
