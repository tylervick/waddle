# Name consistency: WADdle → Waddle

**Status: approved at the brainstorming gate (2026-08-16).**

The app's name is **Waddle**. `WADdle` is a *wordmark* — a visual treatment of
that name, not a spelling of it. Today the repo spells the name four different
ways and treats the stylization as canonical. This spec makes the plain name
canonical everywhere text is typed, confines `WADdle` to artwork, renames the
local checkout and the Orca project to match, and adds a guard so the rule
survives.

## 1. The rule

| Form | Verdict | Where it lives |
| --- | --- | --- |
| `Waddle` | **Canonical.** Prose, docs, Xcode project/scheme/targets, source filenames, App Store display name. | everywhere text is typed |
| `WADdle` | **Wordmark only.** Never typed as text. | `Design/` artwork |
| `waddle` | **Unchanged — already correct.** Bundle ID, UTIs, git remote, asset filenames, Swift method prefixes. | `com.tylervick.waddle`, `tylervick/waddle`, `Design/waddle-mark.png`, `.waddleScrollSurface()` |
| `WADDLE_*` | **Unchanged — already correct.** SCREAMING_SNAKE reads identically for either casing. | test-seam env vars |

Only the first row moves. The 188 lowercase and 96 SCREAMING_SNAKE occurrences
are already consistent under this rule and must not be swept up in the rename.

The `Waddle` occurrences that exist today (5, all in
`docs/app-store/metadata.md`) refer to *unrelated third-party apps* and are not
about this project. They stay as they are.

## 2. In-repo rename

343 occurrences of `WADdle`, in four clusters.

### 2.1 Xcode identity

`App/project.yml` is the single source of truth; `App/*.xcodeproj` is
gitignored and generated by xcodegen.

- `name: WADdle` → `Waddle`
- targets `WADdle`, `WADdleTests`, `WADdleUITests` → `Waddle`, `WaddleTests`,
  `WaddleUITests` (including the `dependencies:` reference in the test targets)
- scheme `WADdle` → `Waddle`, with its `build.targets` and `test.targets` keys
- `CFBundleDisplayName: WADdle` → `Waddle`

`mise run generate` then produces `App/Waddle.xcodeproj`. Delete both
`App/WADdle.xcodeproj` and the stale `App/BoomBox.xcodeproj` left over from
the previous rename — neither is tracked.

### 2.2 Everything that invokes xcodebuild

This cluster must land in the same commit as §2.1 or CI breaks. Occurrences of
`-project App/WADdle.xcodeproj`, `-scheme WADdle`, `-only-testing:WADdleTests`,
and `-only-testing:WADdleUITests` in:

- `mise.toml`
- `.github/workflows/ci.yml`, `ui-tests.yml`, `testflight.yml`, `cold-build.yml`
- `Scripts/archive.sh`, `Scripts/capture-screenshots.sh`, `Scripts/check-red-green.sh`
- `.claude/skills/waddle-filing-an-issue/SKILL.md`

### 2.3 Source

`App/Sources/WADdleApp.swift` → `App/Sources/WaddleApp.swift` via `git mv`,
with the `@main` struct renamed to match. This is the only tracked file whose
*name* carries the stylization.

### 2.4 Prose

`CLAUDE.md` (header and the `-only-testing:` rule), `README.md`, and `docs/`.

Dated artifacts under `docs/superpowers/plans/` and `docs/superpowers/specs/`
are swept too. They are historical records, but the loop's agents read them as
reference, and a plan instructing `-scheme WADdle` is a trap rather than a
preserved fact. The date in each filename already marks them as historical.

`docs/app-store/metadata.md` needs more than substitution: the store name
becomes **"Waddle: WAD Player"**, and the naming rationale is rewritten so the
"WAD hidden inside waddle" argument describes the wordmark rather than the
typed name. The availability finding — that the bare name is held by another
account and the suffix is forced, not chosen — is unchanged and stays.

### 2.5 The guard

`CLAUDE.md` requires that a learning which can be an executable check becomes
one. Add `Scripts/check-name-consistency.sh`: fail if `WADdle` appears outside
`Design/`. Wire it into the same gate as `check-engine-fresh.sh`, give it a
`Scripts/test-check-name-consistency.sh` companion matching the existing
pattern, and add a one-line `docs/learnings/` entry that points at the check
instead of restating it.

## 3. Machine-side migration

Three path-keyed systems move together. `doom-ios-2026` → `waddle`, lowercase,
matching the git remote and the bundle ID.

### 3.1 Directory

```
mv ~/Documents/doom-ios-2026 ~/Documents/waddle
rm -rf ~/Documents/waddle/Vendor/build
```

Git needs no fixup: `.git` uses relative paths and `git worktree list` shows
only `main`. The engine framework is *not* invalidated — `check-engine-fresh.sh`
fingerprints source content, not paths. `Vendor/build` is different: `orca.yaml`
documents that its CMake caches hardcode absolute paths
(`CMAKE_CACHEFILE_DIR`, `*_SOURCE_DIR`), so a cache inherited at a new path
makes `Scripts/build-engine.sh` fail. It regenerates on demand.

### 3.2 Orca

The entire registry is one plain JSON file:
`~/Library/Application Support/orca/profiles/local-default/orca-data.json`.
`doom-ios-2026` appears ~209 times in it:

| Section | Hits | At stake |
| --- | --- | --- |
| `automationRuns` | 111 | `waddle-loop` run history |
| `workspaceSession` | 72 | per-worktree session bindings |
| `worktreeMeta` | 15 | display names, comments, lineage |
| `repos`, `projects`, `projectHostSetups`, `automations` | 6 | the records themselves, incl. the automation's `runPath` |
| `claudeLivePtySessionIds`, `mobileClientTabSelectionsByDeviceId` | 5 | live session + device bindings |

These counts drift between reads — the raw occurrence count moved from 248 to
212 over a few minutes of measurement, because Orca rewrites this file
continuously while running. Treat them as scale, not as a checksum.

**Quit Orca and its daemon first** — it holds this file in memory and will
clobber edits on write. This is the same fact the drifting counts demonstrate.
Back it up, then apply as a single global string replace:

- `/Users/tyler/Documents/doom-ios-2026` → `/Users/tyler/Documents/waddle`
- `/Users/tyler/orca/workspaces/doom-ios-2026` → `/Users/tyler/orca/workspaces/waddle`
- display name `doom-ios-2026` → `waddle` in `repos` and `projects`

Then `mv ~/orca/workspaces/doom-ios-2026 ~/orca/workspaces/waddle`, restart, and
verify with `orca repo list` and
`orca automations show 8a0d5727-9d5c-46a6-b0ef-92d5accf3859`.

**Why not the CLI:** `orca repo add --path` mints a new repo id, orphaning all
248 records; `orca project setup-update --path` is explicitly refused for
repo-backed setups ("Path and availability state changes are only supported for
independent setup records"), and this setup is `method: legacy-repo`. Editing
the JSON is the only route that preserves ids.

**Accepted loss:** `terminal-history/` directories are keyed
`<repoId>::<path>@@<hash>`. The path portion can be renamed, but if the trailing
hash derives from the path, Orca computes a different key and the old scrollback
is orphaned. That is terminal scrollback, not work product; reverse-engineering
the hash is not worth it.

### 3.3 The `boombox` project id — separate step

Orca still knows this project as `github:tylervick/boombox`, predating the
GitHub rename. That string appears 193 times — 132 in `automationRuns`, 49 in
`worktreeMeta`, and 12 across `projects`, `automations`, `repos`,
`workspaceSession`, and `projectHostSetups` — stamped into the historical
record rather than confined to the project record.

This is deliberately **not** bundled with §3.2. It is unknown whether Orca
re-derives the durable id from the git remote on load or treats it as opaque.
If it re-derives, the edit is a no-op; if it half-re-derives, it could mint a
duplicate project. Attempt it only after §3.2 verifies clean, so a failure there
cannot take the rest down, and roll back from the backup if `orca project list`
shows anything unexpected.

### 3.4 Claude session history

Sessions are keyed by slugified cwd, so renaming the directories carries the
history forward:

- `~/.claude/projects/-Users-tyler-Documents-doom-ios-2026` →
  `-Users-tyler-Documents-waddle` — 27 sessions, **and the agent memory
  directory, which lives inside it**
- 57 × `-Users-tyler-orca-workspaces-doom-ios-2026-*` →
  `-Users-tyler-orca-workspaces-waddle-*`
- `~/.claude.json`: one `projects` key (allowlist, MCP servers, trust flags)
  plus 59 `githubRepoPaths` entries
- the 2 memory files that name the old path

The `cwd` values *inside* transcripts are left alone: the directory name is the
lookup key, and those values were true when written. If resume misbehaves they
can be rewritten afterward.

## 4. App Store Connect

`PATCH /v1/appInfoLocalizations/{id}` on the en-US localization — the only one
the record has — setting `name` to `"Waddle: WAD Player"`. Auth via
`Scripts/asc-jwt.sh` and `Scripts/.appstore.env`.

This is a case-only change to a string already owned by this account, and Apple
matches names case-insensitively, so the
`409 ENTITY_ERROR.ATTRIBUTE.INVALID.DUPLICATE.DIFFERENT_ACCOUNT` recorded in
`metadata.md` against the bare name does not apply.

It can still be refused: names are editable only while the version is in an
editable state. If a version is in review, Apple refuses and the change rides
with the next version. Report the refusal; do not work around it.

## 5. Order of operations

1. **Repo rename on a branch → PR.** Never on `main`. Gate: `mise run generate`
   yields `App/Waddle.xcodeproj`, `mise run test` green,
   `Scripts/check-name-consistency.sh` passes, CI green.
2. **Merge**, then
   `orca automations edit 8a0d5727-9d5c-46a6-b0ef-92d5accf3859 --disabled`.
   The loop fires at 09:00/13:00/17:00; a run landing mid-migration would
   create a worktree against a path that is moving.
3. **Machine migration** (§3.1, §3.2, §3.4).
4. **Verify, then re-enable** the automation. `Scripts/loop-precheck.sh` from
   the new path exercises the loop's entry conditions without burning a run.
5. **The `boombox` id** (§3.3), only once 3–4 are clean.
6. **ASC rename** (§4) — independent; can slip without blocking anything.
7. **Restart the Claude session** in `~/Documents/waddle`.

Step 7 is last because the session performing this work runs inside the
directory being moved.

## 6. Rollback

Every step reverses independently:

| Step | Reversal |
| --- | --- |
| Repo rename | revert the PR |
| Directory move | `mv` back |
| `orca-data.json` | restore the backup (Orca also keeps `.bak.0–4`) |
| Claude dirs | `mv` back; `~/.claude.json` from backup |
| ASC name | editable again afterward |

The only irreversible item is the Orca terminal scrollback in §3.2. The only
externally visible one is the ASC display name.

## 7. Out of scope

- **The GitHub repo** — already `tylervick/waddle`.
- **Bundle ID `com.tylervick.waddle` and the UTIs.** Changing them would orphan
  every installed build's saves and document associations, and they are already
  correctly cased under §1.
- **`WADDLE_*` env vars and the lowercase `waddle` family** — correct as-is.
